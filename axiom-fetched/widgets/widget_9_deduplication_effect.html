When more dedup stops helping

Because duplicates inflate token counts, the natural instinct is to crush them as hard as we can, yet FineWeb found that this instinct works against us. Deduplicating within each CommonCrawl snapshot turned out to beat deduplicating globally across all 96 snapshots, since the global pass stripped up to ~90% of the older dumps and that removed data proved to be higher quality. As we flip between the modes below we can watch what gets thrown away and see what it does to the trained model.

Global MinHash treats the whole web as one pile, so that a 2024 page which echoes a 2014 page ends up deleting the older copy. Once we repeat that across 96 snapshots the early dumps are gutted, and the global-deduped ~4T set showed little improvement over non-deduplicated data while it scored far below RefinedWeb, which tells us that the removed old documents were the good ones. Per-snapshot dedup instead keeps each dump honest on its own terms, lands at ~20T tokens, and matches RefinedWeb, which teaches us that dedup is a quality lever we should tune with care rather than a knob we simply push toward maximum aggressiveness.
FineWeb · 15T tokens from 96 CC snapshots. Per-snapshot dedup → ~20T → matches RefinedWeb; global dedup → ~4T → far below. Published results.
The idea that more bytes always means more data is the wrong instinct, and the idea that we should remove every duplicate leads us astray in the same way, because the token count and the quality can move in different directions while only the quality shapes the model we train. aggressive ≠ better
