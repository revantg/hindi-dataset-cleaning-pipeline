A quality filter is a representation decision

Quality filters are tuned on English, so when we crank "quality" up, the tiles that vanish first turn out to be the low-resource languages and non-Latin scripts that the English-trained classifier never learned to read. As we slide the strictness up we can watch Indic content get erased while English survives, and then we can turn on the fix to see representation restored.

Deletion is only part of the story, because the filter can also mangle the script it keeps

MADLAD-400's own self-audit found incorrectly-encoded (detached) viramas across Brahmic scripts (Hindi, Bengali, Tamil, Telugu, Kannada, Malayalam, Odia, Marathi, Nepali…) that needed a correction pass. The virama is the invisible joiner that fuses a consonant cluster, so when we detach it a real syllable becomes a broken half-grapheme that an English-trained classifier reads as garbage and then drops.

✗ detached virama (the bug)
क ् ष
क + ् (virama, floating) + ष shows the joiner separated from its consonants, so the conjunct never forms and the renderer shows three loose pieces.
✓ correct encoding
क्ष
क + ् + ष → क्ष shows the virama bound between its consonants, producing a single conjunct and a single grapheme exactly the way a reader sees it.
These are the same bytes under a single encoding choice, and the detached form is what the corpus actually shipped before the audit caught it. MADLAD-400: 5T noisy → 2.8T clean
V4 reality

We lived through exactly this failure. V4's data selector OPUS steered toward a benchmark proxy that was English-heavy, showing a cosine 0.876 with the English web band, so OPUS systematically under-valued Indic data and would have rejected it, which is the same English-proxy bias this widget demonstrates. Our fix was Always-ON, meaning that 8% of every batch reserved Indic and benchmark data totalling 66.9B tokens across 10 Brahmic scripts, injected invisibly to OPUS, so that every Indic script trained at every growth stage regardless of what the selector wanted. Representation became a protected guarantee rather than a filter outcome.
