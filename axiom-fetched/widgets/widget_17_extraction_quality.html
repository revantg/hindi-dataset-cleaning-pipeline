The same web page, extracted two ways

A crawler hands us raw HTML, and turning that HTML into a training document is the most unglamorous step in the whole pipeline while remaining the step that decides quality far more than any exotic source ever will. A naive strip leaves navigation menus, cookie banners, ghost tags, HTML entities and replacement characters sitting inside the text, whereas a good extractor runs a real clean_text() over the same page. As we select one of the two extractors we can watch the garbage-token count move, because the cleaning below actually runs in JavaScript.

In V4 there was no text cleaning anywhere in the pretraining path, which meant that ghost conversation markers leaked straight into the pretrain text, with [USER] appearing 6 times, [SYSTEM] 2 times and <|endoftext|> 3 times, so the model learned fake chat markers that later fought against the real <|user|>/<|assistant|> special tokens during SFT. Dolma had been cleaned at the document level while remaining dirty at the character level, and this widget is the missing clean_text() pass that we run live over that page.
Extraction is far from an incidental detail, since the very same page can yield two documents where one becomes clean training data while the other teaches the model junk.
