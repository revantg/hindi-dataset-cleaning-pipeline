We test a data recipe cheaply before we commit 1T tokens to it

Every data recipe is a gamble, so the disciplined move that we borrow from the DataComp-LM / FineWeb method is to train a tiny proxy model on each candidate mix and rank them at a fraction of the cost, after which we pour the full run into the winner alone. Because proxy scores correlate with full-run scores, a few cheap experiments buy us a confident decision, and once we run the ablations and read the ranking we can scale the recipe that wins.

The discipline that plays out across three moves
01 · TEST
Many tiny runs
We train a small proxy model on each candidate data mix, and because each run is cheap we can afford to launch a dozen of them.
02 · RANK
Read the correlation
The proxy score tracks the full-run score, so we rank the recipes and discard the weaker ones while the cost is still low.
03 · SCALE
Bet on the winner
We commit the expensive full run to the single recipe that the evidence has chosen for us rather than trusting a hunch.
This is how DataComp-LM matched Llama-3-8B-class MMLU with 6.6× less compute, and it is also how DoReMi reached its baseline ~2.6× faster by tuning the mix on a small proxy.
