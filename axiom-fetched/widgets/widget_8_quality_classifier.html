Build a quality classifier

We cannot afford to pay an LLM to score a trillion tokens, and that constraint is the whole problem we are solving. The approach the modern corpora rely on is to have an LLM score a small sample for educational value so that those labels can train a cheap classifier, and once that model is trained we can run it over the entire corpus for almost nothing. As we set the score threshold below we can watch the tradeoff play out, because every gain in quality comes from throwing away most of the corpus.

The recipe · from LLM labels to a cheap classifier that filters at scale
1LLM scores a sample
An LLM rates a few hundred-thousand docs 0–5 for educational value, and because each doc is expensive to score we only ever run this over a tiny slice of the data.
→
2Train a cheap classifier
Those labels train a fastText / linear model that predicts the score from the text alone, and it does so in milliseconds per doc.
→
3Filter the whole corpus
We run the cheap model over everything and keep the docs that land above a threshold, and that threshold is the decision we get to make below.

Where this recipe comes from
FineWeb-EduLlama 3DCLM
FineWeb-Edu is built in exactly this way, because an LLM scored docs 0–5 for educational value so that a lightweight classifier could learn the score and then filter FineWeb down to a 1.3T-token educational subset that produced dramatically better MMLU and ARC than the unfiltered web. Llama 3 trained its quality classifier along the same lines, using a fastText + DistilRoberta model trained on Llama 2-generated labels. What we can see across both cases is that the lab never hand-labels a trillion tokens and instead teaches a cheap model to do the labelling for it.
The point for V5
The threshold is really a sourcing decision rather than a mere setting, because as we push it upward the quality of what survives rises while the corpus itself collapses, and we are watching ourselves trade volume for value in real time. quality ⇄ volume
